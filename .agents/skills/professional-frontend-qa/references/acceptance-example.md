# Example frontend acceptance criteria

Use and adapt only to the real project:

1. Users can locate the main action without scrolling on standard desktop widths and without guessing on mobile.
2. The page has a consistent visual hierarchy with the existing app; no newly introduced generic dashboard template patterns.
3. Relevant workflows have visible normal, loading, empty, error, success and disabled states.
4. Main layouts are checked at 390, 768 and 1440 CSS px where browser tools exist; no accidental clipping/overflow.
5. Key actions work with mouse and keyboard and have meaningful accessible names.
6. Long Vietnamese labels, product names, currency/date values and error messages do not break the layout.
7. Validation and visual checks are documented honestly with PASS/FAIL/NOT TESTED; do not claim completion without evidence.
8. No unrelated infrastructure, secrets, backend changes, merge or deployment without explicit authorization.
